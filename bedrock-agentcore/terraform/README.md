## Architecture

The infrastructure consists of:

### AWS Resources (29 total)
- **2 IAM Roles**
  - `faultcast-agentcore-exec-v2-dev` - For AgentCore runtime
  - `faultcast-kb-v2-dev` - For Knowledge Base
- **9 IAM Policies** (inline policies for both roles)
- **1 OpenSearch Serverless Collection** (via CloudFormation)
  - Encryption policy
  - Network policy (public access)
  - Data access policy
- **1 Bedrock Knowledge Base**
  - Embedding: Amazon Titan v2
  - Vector index: FAISS engine
- **2 Knowledge Base Data Sources**
  - `knowledge-base-inference/` - ML predictions
  - `maintenance-schedules/` - Work schedules
- **9 SSM Parameters** (configuration storage)

### Agent Configuration
- **Dynamic config generation** from template
- Uses Terraform-created IAM roles
- Deployed to AWS Bedrock AgentCore Runtime
- ARM64 container via CodeBuild

## Deployment

### Automated Deployment (Recommended)

The `deploy.sh` script handles everything:

```bash
cd agent/terraform/scripts
bash deploy.sh
```

**What it does:**
1. ✅ Runs `terraform init` (if needed)
2. ✅ Creates terraform plan
3. ✅ Asks for confirmation
4. ✅ Applies terraform configuration
5. ✅ Updates OpenSearch access policy
6. ✅ Creates Knowledge Base with vector index
7. ✅ Creates 2 data sources
8. ✅ Updates SSM parameters
9. ✅ Generates agent config from template
10. ✅ Deploys agent to AgentCore (optional)
11. ✅ Saves agent ARN for team access

### Manual Deployment

If you prefer step-by-step control:

```bash
cd agent/terraform

# 1. Initialize Terraform
terraform init

# 2. Plan
terraform plan -var-file=environments/dev/terraform.tfvars -out=tfplan

# 3. Apply
terraform apply tfplan

# 4. Setup Knowledge Base
bash scripts/setup_kb.sh

# 5. Deploy Agent
cd ../
agentcore launch
```

## Agent Deployment

### Dynamic Configuration

The agent uses a **template-based configuration** that's populated with Terraform outputs:

**Template**: `agent/.bedrock_agentcore.yaml.template` (committed to git)
**Generated**: `agent/.bedrock_agentcore.yaml` (not committed)

**Placeholders replaced:**
- `{{EXECUTION_ROLE_ARN}}` → Terraform-created IAM role
- `{{AWS_ACCOUNT_ID}}` → Your AWS account
- `{{AWS_REGION}}` → Deployment region
- `{{ECR_REPOSITORY}}` → ECR repository URL
- `{{AGENT_ENTRYPOINT}}` → Path to agent script
- `{{SOURCE_PATH}}` → Agent source directory

### Agent Deployment Flow

```
Terraform Apply
    ↓
Creates: faultcast-agentcore-exec-v2-dev (IAM Role)
    ↓
Deploy script generates .bedrock_agentcore.yaml
    ↓
agentcore launch (uses generated config)
    ↓
Agent deployed with Terraform-managed role
    ↓
Agent ARN saved to SSM + file
```

### Manual Agent Deployment

```bash
cd agent

# Config is already generated by deploy.sh
# Just launch the agent
agentcore launch

# Check status
agentcore status

# Test invocation
agentcore invoke '{"prompt": "What is the status of conveyor-A001?"}'
```

## Team Access

### Getting Agent Information

Team members can get connection details:

```bash
cd agent/terraform/scripts
bash get_agent_info.sh
```

This displays:
- Knowledge Base ID
- Agent ARN
- AgentCore Role ARN
- How to invoke the agent
- Environment variables to export

### Programmatic Access

All key values are stored in SSM Parameter Store:

```bash
# Get Knowledge Base ID
aws ssm get-parameter \
  --name /faultcast/v2/knowledge-base-id \
  --query Parameter.Value \
  --output text \
  --region eu-west-1

# Get Agent ARN
aws ssm get-parameter \
  --name /faultcast/v2/agent-arn \
  --query Parameter.Value \
  --output text \
  --region eu-west-1

# Get AgentCore Role ARN
aws ssm get-parameter \
  --name /faultcast/v2/agentcore-role-arn \
  --query Parameter.Value \
  --output text \
  --region eu-west-1

# List all parameters
aws ssm get-parameters-by-path \
  --path /faultcast/v2/ \
  --region eu-west-1
```

### Invoking the Agent

**Using agentcore CLI:**
```bash
agentcore invoke '{"prompt": "What is the status of conveyor-A001?"}'
```

**Using Python (boto3):**
```python
import boto3
import json

client = boto3.client('bedrock-agentcore', region_name='eu-west-1')

response = client.invoke_agent_runtime(
    agentRuntimeArn='<AGENT_ARN>',
    runtimeSessionId='session-123',
    payload=json.dumps({'prompt': 'Hello'}).encode()
)

print(json.loads(response['response'].read()))
```

**Using AWS CLI:**
```bash
aws bedrock-agentcore invoke-agent-runtime \
  --agent-runtime-arn '<AGENT_ARN>' \
  --runtime-session-id 'session-123' \
  --payload '{"prompt": "Hello"}' \
  --region eu-west-1 \
  output.json
```

## Cleanup

### Automated Cleanup (Recommended)

```bash
cd agent/terraform/scripts
bash cleanup.sh
```

**What it does:**
1. ✅ Auto-detects Knowledge Base ID from:
   - SSM Parameter Store
   - Terraform outputs
   - AWS Bedrock API
2. ✅ Deletes all data sources
3. ✅ Deletes Knowledge Base
4. ✅ Asks to delete agent (optional)
5. ✅ Waits for KB deletion
6. ✅ Runs `terraform destroy`
7. ✅ Removes all 29 resources

### Manual Cleanup

```bash
# 1. Delete agent (optional)
cd agent
agentcore delete

# 2. Delete Knowledge Base
KB_ID=$(aws ssm get-parameter --name /faultcast/v2/knowledge-base-id --query Parameter.Value --output text --region eu-west-1)
aws bedrock-agent delete-knowledge-base --knowledge-base-id $KB_ID --region eu-west-1

# 3. Wait for deletion
sleep 120

# 4. Destroy Terraform resources
cd terraform
terraform destroy -var-file=environments/dev/terraform.tfvars
```

## Troubleshooting

### Deployment Issues

**Problem:** Terraform outputs not found
```bash
# Solution: Check terraform state
cd agent/terraform
terraform state list
terraform output
```

**Problem:** OpenSearch policy update fails
```bash
# Solution: Wait for collection to be ready
sleep 120
bash scripts/deploy.sh
```

**Problem:** KB creation fails with 403
```bash
# Solution: Add your IAM user to OpenSearch policy
CURRENT_USER=$(aws sts get-caller-identity --query Arn --output text)
echo "Add this ARN to OpenSearch data access policy: $CURRENT_USER"
```

**Problem:** Agent config not generated
```bash
# Solution: Check template exists
ls -la agent/.bedrock_agentcore.yaml.template

# Manually generate
cd agent/terraform/scripts
bash deploy.sh
```

### Cleanup Issues

**Problem:** KB ID not detected
```bash
# Solution: Script will skip KB deletion and proceed with terraform destroy
# This is safe if KB was already deleted
```

**Problem:** Terraform destroy fails
```bash
# Solution: Remove problematic resources
terraform state list
terraform state rm <resource>
terraform destroy -var-file=environments/dev/terraform.tfvars
```

**Problem:** Agent still running after cleanup
```bash
# Solution: Manually delete agent
agentcore delete

# Or via AWS CLI
aws bedrock-agentcore delete-agent-runtime \
  --agent-runtime-arn '<AGENT_ARN>' \
  --region eu-west-1
```

### Runtime Issues

**Problem:** Agent invocation fails
```bash
# Solution: Check agent status
agentcore status

# View logs
aws logs tail /aws/bedrock-agentcore/runtimes/<AGENT_NAME>-DEFAULT \
  --log-stream-name-prefix '2025/10/22/[runtime-logs]' \
  --follow \
  --region eu-west-1
```

**Problem:** Knowledge Base not returning results
```bash
# Solution: Sync data sources
KB_ID=$(aws ssm get-parameter --name /faultcast/v2/knowledge-base-id --query Parameter.Value --output text --region eu-west-1)
DS_ID=$(aws bedrock-agent list-data-sources --knowledge-base-id $KB_ID --region eu-west-1 --query 'dataSourceSummaries[0].dataSourceId' --output text)
aws bedrock-agent start-ingestion-job \
  --knowledge-base-id $KB_ID \
  --data-source-id $DS_ID \
  --region eu-west-1
```

## Configuration

### Modify S3 Prefixes

Edit `scripts/create_knowledge_base.py`:
```python
prefixes=['knowledge-base-inference/', 'maintenance-schedules/']
```

### Change Embedding Model

Edit `scripts/create_knowledge_base.py`:
```python
'embeddingModelArn': f'arn:aws:bedrock:{region}::foundation-model/amazon.titan-embed-text-v2:0'
```

### Change Region

Edit `environments/dev/terraform.tfvars`:
```hcl
aws_region = "eu-west-1"
```

### Update Agent Configuration

Edit `agent/.bedrock_agentcore.yaml.template` and redeploy:
```bash
cd agent/terraform/scripts
bash deploy.sh
```

## SSM Parameters

All configuration is stored in SSM Parameter Store under `/faultcast/v2/`:

| Parameter | Description |
|-----------|-------------|
| `aws-region` | AWS region |
| `bedrock-region` | Bedrock region |
| `bedrock-model-id` | Model ID |
| `knowledge-base-id` | KB ID (updated after creation) |
| `knowledge-base-region` | KB region |
| `agentcore-role-arn` | AgentCore IAM role ARN |
| `agent-arn` | Deployed agent ARN |
| `work-schedule-bucket` | S3 bucket name |
| `work-schedule-prefix` | S3 prefix |
| `environment` | Environment name |
| `log-level` | Logging level |
